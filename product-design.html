Why It Works

Evidence first, then pixels, then code.

Research before pixels

Interviews, contextual inquiry, workshops, usability tests. At Valassis I shipped an experimental interface first, so usage data could tell us what to build. At IQVIA, one round of testing found five problems before we had invested further.

Prototypes that make the argument

Sketches, flows, wireframes, then clickable or coded prototypes (HTML, CSS, JavaScript) and generative prototyping. Stakeholders react to behavior, not static screens.

Built with engineering

Component libraries, page models, grooming sessions, front-end support. At Spreedly, I wrote the front end myself.

Scope that survives the calendar

Phased releases and clear MVP lines. At Spreedly, the layout was built to extend, so release two slotted in without a redesign. At Gatorade, when time ran short, I moved to proven e-commerce patterns and shipped.

Case in Depth — Tuner, Valassis

Work only a few experts could do, opened up to analysts.

Business Analysts couldn't optimize the campaigns they owned. Only a few Data Scientists working in Python, R, and Jupyter notebooks could.

Work like this
01

Start with evidence

The lead engineer and I released an experimental interface to a small group of Data Scientists. Usage data showed which optimizations people actually made.

02

Discover the workflow

Stakeholder interviews, contextual inquiries, and a design workshop. In the workshop, participants sketched on printed interface shells.

03

Narrow, then explore

Static wireframes to settle scope. Rapid prototyping for interaction patterns once the core was clear.

04

Deliver and stay

Components and page models to engineering. Embedded through grooming across two quarters, with a feedback loop after launch.

What I'd change: clearer system feedback after each optimization.

Process

Four steps, no handoff cliff.

Step 1

Understand

Stakeholder interviews, user interviews, observation.

Step 2

Structure

Sketches, user flows, wireframes.

Step 3

Test

Interactive prototypes, usability testing.

Step 4

Hand off

Components, page models, front-end support, feedback after launch.
